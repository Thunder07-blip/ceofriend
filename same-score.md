# CEOfriend: Final Mathematical Scoring Logic

This document serves as the absolute source of truth for the CEOfriend system's core mathematical logic, specifically reflecting the **Uncertainty Risk** and **Baseline Floor** models that successfully prevent zero-collapse scoring on low-signal repositories.

---

## 1. File Risk Breakdown ($R_{file}$)

Each analyzed file is evaluated across 5 deterministic dimensions, guaranteeing diverse sensitivity.

### 1.1 Volatility ($V_{vol}$) - Weight: **25%**
Measures stability based on recent churn.
* **Floor Check:** A baseline of `10` is enforced to prevent collapse on dead files.
* **Formula:** `min(100, max(10, recentCommits * 2))`

### 1.2 Bug Density ($V_{bug}$) - Weight: **35%**
Identifies localized fragility based on known defect history.
* **Absence Penalty:** If `0` bugs are logged, standard scaling is bypassed and a default unmeasured uncertainty baseline (`10`) is assigned.
* **Formula:** `bugs == 0 ? 10 : min(100, (bugs / max(1, totalCommits)) * 100)`

### 1.3 Ownership ($V_{own}$) - Weight: **10%**
Measures bus-factor and tribal knowledge compartmentalization.
* `1` contributor = **100**
* `≤ 3` contributors = **60**
* `≤ 5` contributors = **30**
* `> 5` contributors = **20**

### 1.4 Test Coverage ($V_{test}$) - Weight: **15%**
Checks for the presence of sibling test suites protecting the logic.
* **No tests found:** `100` penalty
* **Tests found:** `20` safe baseline

### 1.5 Uncertainty Risk ($V_{uncert}$) - Weight: **15%**
Quantifies strictly "unmeasured" and stagnant conditions so that an absence of signal does not falsely evaluate as safety. Evaluated additively up to `100`.
* `0 Total Commits` = **+30**
* `0 Recent Commits` = **+20**
* `0 Tracked Bugs` = **+10**

## 2. Risk Compilation & Importance Weights

The raw file risk is the sum of the weighted vectors:
$$R_{base} = (V_{vol} \times 0.25) + (V_{bug} \times 0.35) + (V_{own} \times 0.10) + (V_{test} \times 0.15) + (V_{uncert} \times 0.15)$$

### 2.1 File Differentiation ($W_{imp}$)
To guarantee proper resource triage logic, files undergo string-matching for critical business paths to artificially amplify risk on vital systems over generic structure.
* **Payment Systems** (`payment`): $1.5\times$
* **Access/Auth** (`auth`): $1.2\times$
* **Standard/Generic**: $1.0\times$

**Final File Risk Score:**
$$R_{final} = \max(0, \min(100, R_{base} \times W_{imp}))$$

**File Health Score:**
$$H_{file} = 100 - R_{final}$$

---

## 3. Repository Aggregation

The final health score of the entire repository is calculated as a **weighted average** of the top 20 hotspot files analyzed.
Files with a higher absolute number of tracked `commits` are granted higher gravity in evaluating overall component health, mapping strictly to architectural dominance rather than raw unmeasured footprint.

## 4. Financial Impact Exposure (From `ImpactAgent`)

After predictive risks are quantified, they integrate directly into the definitive financial loss mapping.

**Formula:** 
$$E_{loss} = P_{fail} \times C_{hour} \times T_{down} \times U_{impact} \times (1 + \frac{R_{pred}}{50})$$

* **Failure Probability ($P_{fail}$)**: $R_{final} / 100$
* **Hourly Cost ($C_{hour}$)**: Mapped to systemic category (e.g., Revenue = ₹25,000, Ops = ₹15,000...)
* **Downtime ($T_{down}$)**: Tiered based on raw $R_{final}$ (e.g., 4h, 2h, 1h).
* **Company Scale Factor ($U_{impact}$)**: Dynamically bound to the specific `$Yearly Turnover$` context.

This exact mathematical loop validates all end-of-chain figures generated by CEOfriend dynamically.
