# CEOfriend: AI Agent Architecture

This document maps the entire linear orchestration pipeline from standard GitHub Repository URL ingestion to the final generated C-suite financial executive report. The architecture relies on deterministic models mapping engineering context deeply into financial boundaries.

---

## 0. Orchestrator (`src/lib/orchestrator.ts`)
**Goal:** Coordinate the continuous execution of all internal sub-agents in a sequential, deterministic loop.
**How it Achieves it:**
- Wraps each individual agent within a strict `try-catch` bounded system, allowing the pipeline to extract partial metrics even if one segment faces API timeouts.
- Intercepts all output data upon termination, writing the deterministic output vectors automatically into `scoring-logs.csv` to ensure offline tracing parity.
- Validates the overall schema transitions between steps.

---

## 1. Repo Agent (`src/modules/repoAgent.ts`)
**Goal:** Ingest raw third-party repository data, strip out the noise, and extract high-signal structural "hotspots" to bypass GitHub token rate limiting.
**How it Achieves it:**
- Instead of downloading the repository globally into a local runtime, it queries the GitHub Tree API recursively.
- It parses raw metadata to detect `auth`, `payment`, and `critical` systemic paths organically.
- Sorts over 1000s of files using a prioritization matrix (Bugs, Commits, Business Priority paths) to select the definitive "Top 20 Hotspots".
- It then natively executes strict REST requests *only* for the targeted Top 20 to extract individual file `contributors`, `commit history`, and `file bytes`.

---

## 2. Risk Scoring Agent (`src/modules/riskAgent.ts`)
**Goal:** Map raw GitHub engineering commits and bugs directly into quantitative baseline technical risk.
**How it Achieves it:**
- Reads the raw telemetry generated by the Repo Agent.
- Applies a robust mathematical matrix enforcing **Uncertainty Risk**. Flat, old, un-touched code does *not* equal safe code.
- Evaluates 5 dimensions deterministically:
  1. `Volatility` (25% Weight) - Code churn scale
  2. `Bug Density` (35% Weight) - Relative volume of open deflections
  3. `Test Coverage` (15% Weight) - The absence of parallel logic testing
  4. `Ownership`     (10% Weight) - Centralized bus-factor risk on sole contributors
  5. `Uncertainty`   (15% Weight) - Strict +30 thresholds applied to stagnant artifacts without data.
- Automatically applies an *Extension Identifier* priority, boosting intrinsic baseline risks to configuration files, core logic, or `.sol` smart contracts.

---

## 3. Prediction Agent (`src/modules/predictionAgent.ts`)
**Goal:** Forecast the forward-looking 90-day trajectory of the repository structure based on the raw risk limits generated by the Risk Agent.
**How it Achieves it:**
- Evaluates the gradient of commits vs relative bugs vs raw timeframe. 
- Distinguishes inherently stable architectures from dynamically scaling logic loops that will accelerate toward breaking.
- Assigns a forward-looking Failure Likelihood and extrapolates frequency, determining statistically how likely the specific module will break in production over the coming quarter.

---

## 4. Business Impact Agent (`src/modules/impactAgent.ts`)
**Goal:** Convert all software-oriented prediction limits mapping into deep financial loss logic ($).
**How it Achieves it:**
- Ingests the CEO's active variables provided on the frontend (e.g., `Yearly Turnover: 1 Crore`).
- Generates base structural scaling (e.g. `1 Crore Turnover = 0.1x System Scale`).
- Scans predicted files to append Business Values (e.g. `auth files` = User Action = `₹80,000/hr baseline loss`).
- Executes the finalized equation guaranteeing deterministic variance over every file tested: 
  > $E_{loss} = P_{fail} \times (C_{hour} \times Scale) \times T_{down} \times U_{impact} \times F_{exp}$

---

## 5. Report Agent (`src/modules/reportAgent.ts`)
**Goal:** Ingest the fully calculated payload matrices into an un-formatted JSON interface and generate a readable, actionable C-Suite brief that is digestible exclusively by a non-technical corporate business leader.
**How it Achieves it:**
- Parses the top 5 largest potential monetary losses identified by the Impact Agent.
- Calls the overarching Gemini LLM, instructing it statically to drop all developer jargon.
- Outputs clean Markdown consisting. Specifically forces the explicit delivery of the calculated `$Exposure` integers alongside English qualitative summaries. 
- Automatically catches LLM blackout errors, generating a clean generic string in place of the LLM mapping so the UI never crashes for the end-user facing API limitations.
